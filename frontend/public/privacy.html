Where your image goes depends on the engine you choose

LuminaBG offers on-device processing and optional cloud models. Check the selected engine before you start if an image is sensitive.

Browser engine: processed on your device

The Browser engine runs the background-removal model in your browser tab. The app does not send your original image to its Vercel processing endpoint when you use this engine. Your browser still needs to download the model files needed to run it.

remove.bg engine: sent to the remove.bg API

If you select remove.bg, the app sends the image to a LuminaBG serverless function, which forwards it to the remove.bg API and returns the processed PNG. The function removes its temporary upload file during the request. The remove.bg service processes the image, so its own handling and retention terms apply.

Hugging Face models: sent to the configured Space

If you choose U2-Net, U2-Net-P, ISNet, BiRefNet, or Silueta, the browser sends the image to the configured Hugging Face Space for processing and retrieves the result from that Space. The Space operator and Hugging Face service handle that request under their own practices and terms.

In short: choose Browser when you want the image processed on-device. Choosing a remote engine means the image is sent to that engine's provider. LuminaBG does not create user accounts or an image library; this app code does not intentionally save user images to a LuminaBG account or database.

What the app stores in your browser

LuminaBG saves your light or dark theme preference in your browser's local storage. The app does not ask you to create an account. The image processing and download flow is session-based; no image gallery is provided.

Questions or corrections

For code-level questions, visit the LuminaBG source repository. For the most current details about third-party processing, consult the selected provider's own privacy and service information.
